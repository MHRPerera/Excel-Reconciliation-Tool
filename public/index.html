Compare two reports

Upload two spreadsheets to compare their structure and contents — matching columns, matched and unmatched rows, duplicates, and optional cell-by-cell differences — then download it all as one report. Large files are streamed to disk and compared using an embedded database, not held in memory, so multi-gigabyte workbooks are supported.

How it works

  1. Upload. Both files stream straight to disk on the server as they upload — nothing is held fully in browser or server memory.
  2. Configure. Pick which sheet and which row holds column headers for each file.
  3. Choose key columns. These identify a row (e.g. an ID) and are used to match rows between the two files and to detect duplicates within each file.
  4. Optional cell comparison. Pick specific columns to compare value-by-value for rows that match on the key.
  5. Compare. Each file is streamed row-by-row into a local SQLite database. All the heavy joins (matched / only-in-A / only-in-B / duplicates) run inside SQLite using indexes, not in JavaScript, so memory use stays flat regardless of file size.
  6. Report. The output workbook is streamed directly to disk sheet by sheet, so even very large detail sheets never need to fit in memory at once.

Limits & tips

  • Supported formats: .xlsx and .xls. (.xls files still go through the same streaming reader.)
  • Max upload size defaults to 5 GB per file — configurable via the MAX_FILE_MB environment variable on the server.
  • If a workbook has several large sheets, picking the sheet you need as the first sheet is faster — the reader streams sequentially through sheets in file order.
  • Disk space: the server needs roughly the size of both input files again for the working database, plus space for the output report. Make sure the host has enough free disk.
  • If you deploy this behind a reverse proxy (nginx, etc.), raise client_max_body_size to match your upload limit.
  • A comparison session (uploaded files + working database) is automatically cleaned up an hour after it's created.
